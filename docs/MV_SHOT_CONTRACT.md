# 장면 지시 계약 v0.1 — 종이별에서 문으로

상태: `mv_scene_plan.py`와 예시·검증 테스트로 수치 계약을 구현했다. 현재
`MVArtRenderer`는 이 규격을 실행하지 않는다. 원화 5장을 시험했으나 자산 품질은
통과하지 못했고 이 계약을 실행하는 렌더러는 아직 구현하지 않았다.
파일·출처 검사를 통과해도 알파·그림 등록·실제 가사와 cue·미술 품질을 보장하지 않는다.
다음 렌더러 경계는 [MV_RENDER_PLAN.md](MV_RENDER_PLAN.md)에 기록한다.
색·조명은 [미술 기준](MV_ART_BIBLE.md)의 `color-v2`를 따른다. 고유색을 유지해도
장면광 아래 보이는 색은 달라질 수 있다. v2 조명 설계는 아직 렌더러가 실행하지 않는다.

품질·자동화 구분은 [MV_QUALITY_GATE.md](MV_QUALITY_GATE.md)를 따른다.
본 문서의 모든 장면과 인물은 독립적으로 설계한 예시다. 특정 레퍼런스에서 이 동작을
관찰했다는 의미가 아니다.

## 1. 단위와 시간

- 마스터 캔버스: 960×540, 16:9, 24fps, 15초, 정확히 360프레임.
- 전체 시간은 정수 프레임을 기준으로 한다. 컷 범위는 `[start_frame, end_frame)`.
- 월드 좌표는 픽셀 단위, 원점은 왼쪽 위, 오른쪽이 +x, 아래가 +y.
- 인물 로컬 원점은 두 발 사이 바닥. 아래 예시에서 인물 높이는 330, 바닥 y는 470.
- 카메라는 2D 직교 투영이다. `screen = canvas_center + (world - camera.center) * zoom`.
  GPU의 실제 3D 카메라 추정이나 미검증 공간 복원을 뜻하지 않는다.
- 포즈 자산은 같은 기준 원점·크기·시점을 사용한다. 이미지 크기 변화로 몸이 커졌다
  작아지는 현상을 렌더러가 장면 효과로 숨기지 않는다.
- 가사/음악 cue는 정수 프레임과 원래 초 단위 시점을 함께 보존한다. 자동 정렬 여부와
  사람 수정 여부를 각각 기록한다.

## 2. 프로젝트 필수 항목

```json
{
  "format": "voice-motion-directed-scene",
  "version": 1,
  "stage": "art_action_study",
  "canvas": {"width": 960, "height": 540, "fps": 24, "frames": 360},
  "audio": {"sha256": "required-input-hash", "relative_asset": "audio/source.wav", "rights": "required-evidence"},
  "lyrics": {"source": "fixture_not_asr", "timing_source": "planning_placeholder", "segments": []},
  "music_cues": [],
  "assets": [],
  "actors": [],
  "props": [],
  "shots": [],
  "events": [],
  "production_record": {"candidate_budget": {}, "selected_by": "human_art_study", "manual_edits": [], "failures": []}
}
```

이 계약의 JSON에는 원음 샘플이나 절대 호스트 경로를 포함하지 않는다.
음원은 job 내부의 상대 자산 참조와 해시로 연결한다.

`stage`는 `art_action_study` 또는 `automatic_evaluation`이다. 후자는
`selected_by`에 실제 자동 선택기와 버전을 기록한다. 사람이 후보를 선택한 경우
`automatic_evaluation`의 성공으로 취급하지 않는다.

## 3. 자산·인물·소품

자산 공통 필드:

| 필드 | 의미 |
|---|---|
| `id`, `relative_asset`, `sha256` | 실행 디렉터리 내부 파일만 참조. 외부 URL·임의 절대 경로 금지 |
| `kind` | `rgba_image`, `vector`, `rig`, `pose_sequence`, `video_layer`, `mask` |
| `provenance` | 자체 제작 / 실제 모델 ID·커밋·라이선스·프롬프트·seed·후보 번호 |
| `bounds`, `pivot`, `anchors` | 기준 좌표계, 손목·별 접점·주머니 등 이름 있는 점 |
| `masks` | 얼굴·손·앞팔·몸통·소품의 가림 순서를 확인할 수 있는 레이어 |
| `review` | 미검토 / 채택 / 탈락, 선택자와 탈락 이유. 모델 생성 사실이 품질 통과를 뜻하지 않음 |

인물 `courier_01`의 불변 특성:

- 성인, 검은 단발, 코랄 우비, 먹색 바지·신발, 초승달 핀.
- 기준 시점: 화면 오른쪽을 향한 약한 3/4. 첫 증명에서는 자유로운 시점 회전을 요구하지 않는다.
- 기본 root `[360,470]`, 기준 높이 `330`.
- 필수 앵커: `pocket`, `right_shoulder`, `right_elbow`, `right_wrist`, `right_grip`, `eye_target`.
- 표정: 집중 → 결심 → 발견. 눈 깜박임·입 모양만 바뀌는 것으로 감정 연기를 완료했다고 보지 않는다.
- 표현 방법은 검증한 `rig`, `pose_sequence`, `video_layer` 중 선택한다. 미구현 자동 리깅을 가정하지 않는다.

소품 상태:

| ID | 시작 상태 | 가능한 상태 | 지켜야 할 조건 |
|---|---|---|---|
| `paper_star_01` | `pocket_hidden` | `held_folded`, `held_opening`, `released`, `floating_open`, `door_seal` | 한 개만 존재. 같은 ID·재질 기준·선 굵기·기본 모양을 유지. 조명에 따른 색 변화는 허용하며 손에서 분리되는 프레임 명시 |
| `door_01` | `absent` | `tracing`, `closed_outline`, `opening`, `open` | 별에서 출발한 선이 문을 만들어야 함. 미리 완성된 문을 무관하게 페이드인하지 않음 |

`paper_star_01`의 원래 화면 크기는 36×36. 열림 때 최대 72×72.
`door_01`의 기본 월드 범위는 `[640,140,800,470]`, 안쪽 마스크 `[650,150,790,470]`.
별은 마지막에 문의 윗중앙 `[720,140]`에 남는다.

## 4. 상태와 행동 실행

모든 shot은 `initial_state`, `actions`, `keyposes`, `camera`, `typography`,
`exit_state`를 가진다. 다음 컷의 `initial_state`는 이전 `exit_state`를 상속한다.
별을 손에 든 상태에서 다음 컷이 시작됐는데 소품 ID가 새로 생기는 것은 오류다.

지원할 행동의 최소 의미:

| 행동 | 입력/출력 상태 | 필수 채널 |
|---|---|---|
| `reach_and_extract` | `pocket_hidden → held_folded` | 팔·손·주머니 가림 관계. 소품은 손에 붙어 있어야 함 |
| `offer` | `held_folded → held_folded` | 어깨·팔꿈치·손목의 호 운동과 몸의 무게 이동 |
| `open_hand` | `grip_closed → grip_open` | 최소 쥠/중간/펼침의 형태. 손 이미지의 단순 알파 페이드만으로 처리하지 않음 |
| `detach` | `held_* → released` | 붙잡힌 마지막 프레임과 분리 첫 프레임에 위치 연속성 보장 |
| `follow_arc_and_unfold` | `released → floating_open` | 별의 명시적 위치 곡선·회전·접힘 상태. 인물 전체 흔들림과 무관하게 움직임 |
| `trace_door` | `door.absent → door.closed_outline` | 별에서 출발한 선/종이 띠 경로와 진행률 |
| `open_door` | `closed_outline → open` | 문 안쪽의 reveal mask, 가림·공간 전환 상태 |
| `look_at` | 시선/머리/어깨 방향 변화 | 목표 물체 좌표와 시선 이동의 시작·도착 프레임 |

시각적 준비·이동·멈춤은 실제 채널로 기록한다. `easing` 문자열 하나나
`pose='reach'`만 적고 행동이 구현됐다고 간주하지 않는다. 자세 교체 경계에서
형태가 녹는 크로스페이드나 무의미한 광학 흐름도 통과하지 않는다.

## 5. 세 컷의 구체적인 키포즈·카메라

표의 프레임은 프로젝트 전체 프레임이다. 의도한 음악 구간이 결정되면 cue에 맞춰
바꿀 수 있으나 접촉·분리·상태 상속 조건은 유지한다.

### S01: 0–96프레임 — 종이별을 꺼내 내민다

- 카메라: 중심 `[410,290]`, zoom `1.1`, 회전 `0`. 손·주머니·표정이 함께 보이는 구도.
- 주인공 root `[360,470]` 고정. 발의 고정은 손 동작을 잘 읽히게 하기 위한 연출이다.
- 별은 처음 주머니 뒤에 있고, 손이 집은 시점부터 `right_grip`에 부착되어 함께 나온다.
- 정확한 부착 이벤트는 24프레임이다. 이때 손의 grip과 주머니 속 별의 접점이
  같은 월드 좌표에 있다. 별은 손에 붙은 뒤에도 주머니 앞면 마스크에 가려 있다가
  24–42프레임의 이동 중 점진적으로 드러난다. 42프레임에 손 위로 갑자기 생성하지 않는다.

| 프레임 | 핵심 포즈 / 상태 | 오른손 로컬 앵커 예시 | 준비·이동·멈춤 |
|---|---|---|---|
| 0 | 주머니 위에 손, 집중 | 손목 `[35,-155]`, 별은 hidden | 정지로 인물·방향을 읽을 시간 |
| 18 | 손이 주머니 안으로, 어깨가 내려감 | 손목 `[25,-145]` | 행동 전 짧은 준비 |
| 24 | 주머니 속 별을 잡음, `attach` 이벤트 | grip `[25,-165]`, 별 중심 월드 `[385,305]` | 상태는 `held_folded`, 주머니 앞면의 가림 유지 |
| 42 | 별을 꺼내며 팔꿈치가 바깥으로 | 손목 `[85,-245]` | 손은 직선 순간이동이 아니라 호로 이동 |
| 78 | 별을 앞에 내밀고 시선이 별에 닿음 | 손목 `[140,-230]`, 별 중심 월드 `[500,240]` | 주동작 정지, 옷/머리의 작은 후행 운동 |
| 95 | 같은 위치를 유지 | grip에 부착, 별 크기 36 | 다음 컷과 위치·상태 연결 |

어깨·팔꿈치도 함께 키잉하며 앵커만 이동시키고 팔을 늘리는 방식은 피한다.
자산의 실제 접점은 원화가 정해진 뒤 보정하고 기록한다.

### S02: 96–216프레임 — 손을 펴 별을 놓는다

- 카메라: 중심 `[500,240]`, zoom `1.8`, 회전 `0`. S01의 같은 순간을 확대해 잇는다.
- 얼굴은 왼쪽, 손과 별은 중앙. 얼굴 일부를 의도적으로 자를 수 있으나 손·별은 전부 보인다.
- 분리 이벤트 전에는 별의 위치를 독립 경로로 움직이지 않는다.

| 프레임 | 핵심 포즈 / 소품 위치 | 상태 |
|---|---|---|
| 96 | S01 끝의 손/별 그대로 | `held_folded`, grip closed |
| 114 | 손가락이 반쯤 펴지고 손목이 조금 회전 | `held_opening`, 손과 별 접촉 유지 |
| 131 | 손바닥이 펴진 마지막 접촉 순간 | grip open, 별은 아직 attached |
| 132 | 같은 위치·속도에서 별이 분리 | `released`, attachment 제거 |
| 168 | 별이 `[620,180]`에 도달, 인물 시선이 따라감 | `released`, 열림 0.5, 회전 +60도 |
| 192 | 별이 `[680,155]`를 지남 | `floating_open`, 열림 1.0, 회전 +120도 |
| 215 | 별이 `[720,190]`, 손은 열린 채 아래로 천천히 회수 | `floating_open`, 회전 정지 시작 |

별의 경로는 `[500,240] → [620,180] → [680,155] → [720,190]`를 지나는
검증된 cubic path로 기록한다. 접촉 직후 위치나 속도가 불연속이면 실패다.
별이 열리는 과정은 설계한 접힘/종이 패널 변화로 만들며 단순히 커지기만 하면 실패다.

### S03: 216–360프레임 — 별에서 문이 생기고 시점이 들어간다

- 첫 프레임 카메라: 중심 `[540,275]`, zoom `1.0`. 별·주인공·문이 생길 공간을 함께 보여준다.
- 인물 root는 `[360,470]` 유지. 시선·머리·어깨를 문으로 돌린다.
  첫 증명에서 미검증 보행 생성까지 추가하지 않는다.
- 문 생성이 읽힌 뒤에만 카메라가 이동한다. 동작을 빠른 줌으로 가리지 않는다.

| 프레임 | 행동 / 카메라 | 상태 |
|---|---|---|
| 216 | 이전 별 위치 `[720,190]` 유지 | door absent |
| 228 | 별이 `[720,140]`에 오르고 종이 띠가 첫 모서리로 출발 | `door.tracing`, star `door_seal`로 이행 |
| 264 | `[720,140]→[800,140]→[800,470]→[640,470]→[640,140]→[720,140]` 윤곽 완성 | `closed_outline`; 별이 위에 남음 |
| 288 | 깊이가 있는 살구빛 실내 reveal 완료, 주인공이 문을 봄 | `open`; 종이 띠와 별의 연결 유지 |
| 312 | 중심 `[620,280]`, zoom `2.0` | 카메라가 문으로 접근 |
| 348 | 중심 `[720,280]`, zoom `7.0`, 문 안쪽 마스크가 화면을 채움 | 시점이 통과한 상태 |
| 359 | 살구빛 공간에 같은 별의 작은 흔적, 정지 | 종결, 갑작스러운 검은 프레임 없음 |

문의 선을 따라가는 종이 띠는 단일 원본의 연결 경로다. `door`가 완성되는 구간에서
별이 임의의 장식으로 교체되거나 사라지지 않는다. 마지막 별의 흔적은 같은 prop의
의도된 시각적 회수이며 새로운 별 인스턴스를 몰래 만드는 방식이 아니다.

## 6. 렌더 가능한 shot 레코드 예시

다음 예시는 완성된 입력 파일이 아니라 필수 필드와 상태 제어 형태다. 실제
asset 해시·rig 핸들·음악 cue가 채워지기 전에는 `render_ready=false`로 둔다.

```json
{
  "id": "S02",
  "range": [96,216],
  "render_ready": false,
  "initial_state": {"inherit": "S01.exit_state"},
  "camera": {"projection":"orthographic2d","center":[500,240],"zoom":1.8,"rotation_deg":0},
  "actions": [
    {"id":"open","kind":"open_hand","actor":"courier_01","hand":"right","range":[96,132],"keyposes":[96,114,131]},
    {"id":"release","kind":"detach","actor":"courier_01","prop":"paper_star_01","frame":132,"require_attachment":"right_grip"},
    {"id":"flight","kind":"follow_arc_and_unfold","prop":"paper_star_01","range":[132,216],
     "position_keys":[{"frame":132,"xy":[500,240]},{"frame":168,"xy":[620,180]},{"frame":192,"xy":[680,155]},{"frame":215,"xy":[720,190]}],
     "interpolation":"cubic_continuous","fold_keys":[[132,0],[168,0.5],[192,1],[215,1]]}
  ],
  "keyposes": [
    {"frame":96,"actor_asset":"A03","hand_asset":"H01","registration":"courier_01"},
    {"frame":114,"actor_asset":"A03","hand_asset":"H02","registration":"courier_01"},
    {"frame":131,"actor_asset":"A04","hand_asset":"H03","registration":"courier_01"}
  ],
  "typography":{"lyric_segment_ids":[],"preferred_box":[680,45,920,180],"avoid":["face","right_hand","paper_star_01"],"animation":"short_reveal_then_hold"},
  "exit_state":{"paper_star_01":{"state":"floating_open","world_xy":[720,190],"attached_to":null},"courier_01":{"right_hand":"open"}}
}
```

액션마다 사용한 보간·마스크·포즈 자산·채널이 실제 렌더러에서 지원되는지 확인한다.
알 수 없는 액션을 무시하거나 기존 `sway`로 바꾸지 말고 실행 불가로 보고한다.

## 7. 타이포그래피와 음악 cue

- 가사는 원문을 보존하며 실제 음원/ASR/사용자 수정/임시 연구 문구를 구분한다.
- S01: 오른쪽 위 여백, S02: 손과 얼굴을 피한 오른쪽 위, S03: 문과 인물이 없는
  왼쪽 위를 우선한다. 카메라 움직임 뒤에도 겹침 검사를 다시 한다.
- 실제 문장 길이와 마스크를 검사해 위치·줄 수를 확정한다. 고정 박스라고 무조건 통과하지 않는다.
- 한국어는 의미 단위, 영어는 단어 단위 줄바꿈. 글자를 읽기 위해 눈을 급히 옮겨야 하는
  과도한 흔들림·상시 하단 자막 바·배경과의 낮은 대비는 피한다.
- 첫 증명에서 가사는 사건을 보완한다. ‘가사가 없으면 무슨 행동인지 모르는’ 결과는 탈락이다.
- `music_cues`: `{id,source,time_seconds,frame,confidence,manual_adjustment}`.
  `source`는 모델 추정·신호 검출·사람 연구 표시를 구분한다.
- 예정 cue는 추출 완료, 분리 순간, 문 열림의 3개다. 실제 음원을 듣기 전에 cue가
  박자·드롭과 일치한다고 주장하지 않는다.

## 8. 실행 전 검사와 증거

실행 전 검사:

1. 범위에 빈틈·겹침이 없고 전체 360프레임을 덮는다.
2. 모든 자산 파일·해시·라이선스·등록 좌표와 레이어가 존재한다.
3. 액션이 구현돼 있고 시작 상태가 맞는다. 예: `detach` 직전에 해당 grip에 붙어 있다.
4. 컷 경계의 prop ID·부착 상태·월드 위치가 이어진다.
5. 손·소품 접촉, 인물 바닥·팔다리 길이, 카메라 확장 영역을 확인한다.
6. 중요한 동작·얼굴·가사 영역을 가리는 레이어가 없다.
7. 실제 실행 자원 계획이 승인된 독립 프로젝트 환경 안에 있고 공유 자원 충돌이 없다.

검토 증거:

- 세 컷의 시작·주요 동작·종료 프레임과 컷 경계 전후 프레임.
- 손과 별의 접촉/분리 구간 확대 재생.
- 원음 포함 정상 속도 영상, 음소거 영상, 가사 없는 행동 확인 버전.
- 자동 cue와 최종 프레임 차이, 음악·가사 시간 출처.
- 후보 전체 목록, 선택·탈락 이유, 사람 수정 내역, 출력 해시와 SDK 실행 ID.

정지 프레임 세 장의 성공은 애니메이션 성공이 아니다. 한 곡의 수작업 연구 성공은
입력 파일 하나로 끝나는 자동 제품 성공이 아니다. 문서의 이름이나 필드 존재만으로
구현 완료를 표시하지 않는다.
