# 15초 directed-scene 렌더 제작 설계

상태: 설계만 작성했다. 신규 렌더러·원화·포즈·레이어·영상은 아직 만들지 않았다.
현재 13개 자산은 모두 pending이며, 이 문서를 제작 성공이나 품질 통과로 표시하지 않는다.
이 문서는 기존 `mv_engine.py`와 `MVArtRenderer`를 개선 완료했다고 주장하지 않는다.

관련 문서:
[품질 기준](MV_QUALITY_GATE.md), [장면 계약](MV_SHOT_CONTRACT.md),
[모델 조사](MV_MODEL_RESEARCH.md), [15초 계획 JSON](../examples/paper-star-15s.scene.json).

## 1. 제작 목표와 경계

목표는 ‘주인공이 종이별을 꺼낸다 → 손을 펴 놓는다 → 같은 별에서 문이 생긴다’는
15초·3컷이 실제 애니메이션으로 설득력 있게 보이게 만드는 것이다. 완성 원화 위에
줌·회전·사인함수만 얹거나, 팔 조각을 피벗에서 회전시키는 결과로 되돌아가지 않는다.

원화의 형태와 연기는 그려진 포즈와 검증한 중간 동작이 담당한다. 수치 계산은 접촉·
위치·타이밍·카메라·레이어 연속성을 제어한다. 좋은 애니메이션을 IK가 자동으로
만든다는 전제는 두지 않는다.

이 시제품은 사람이 콘티·원화 후보·수정 결과를 선택할 수 있는 **미술·동작 연구**다.
15초가 성공해도 전곡 자동화, 노래 한 개만으로 완성되는 제품, 특정 작가와 동급의
품질이 증명되는 것은 아니다.

## 2. 현재 코드 검토: 할 수 있는 것과 부족한 것

아래는 작성자 자신의 코드 검토다. 독립된 다른 리뷰어의 검토 결과와 혼동하지 않는다.

현재 `mv_scene_plan.py`가 확인하는 것:

- 정수 프레임 컷 범위, 360프레임 전체 커버, 자산 ID·상대 경로·출처·검토 상태.
- 손의 고정 길이 2D IK, grip 부착, 132프레임에서 위치·속도가 이어지는 분리.
- 같은 별에서 시작하는 문 윤곽, 열린 문 뒤의 카메라 통과, 액션과 실제 수치 채널의 연결.
- 자동 평가로 표기하면서 사람 선택·수정을 기록하는 모순, 선택된 생성 후보 ID와 로그의 불일치.
- pending 자산을 렌더 준비 완료로 취급하지 않는 입력 경계.

실제 렌더를 연결하기 전에 보완할 것:

| 검토 결과 | 현재 한계 | 신규 렌더러의 필수 대응 |
|---|---|---|
| `render_ready`의 의미 | 파일 존재·해시·출처·검토 기록은 확인하지만 이미지 디코딩·알파·등록 좌표·손 접촉 형태를 확인하지 않음 | 별도의 media/registration preflight를 통과해야 `compiled_for_render`가 됨. 파일 검사만으로 작품 품질을 통과시키지 않음 |
| 실제 가사·음악 cue | `typography`는 객체 존재를 확인하는 수준. 연구용 임시 문구·빈 cue가 실제 음원 정렬과 같지 않음 | 실제 음원·가사 출처·구간·cue와 글자 배치를 확정하고 pending 음악/타이포 항목을 거부 |
| 자산 bundle | 현재 예시는 핵심 포즈를 단일 PNG 경로로 예약. 중간 그림·손 전후 레이어·배경 깊이 파일이 없음 | 필요한 ID를 실제 `pose_sequence`/레이어 bundle로 확장하고 구성 파일 전체의 경로·해시·출처까지 검사 |
| 실행 비용 | `sample_scene()`가 호출마다 전체 계약과 모든 프레임의 IK/trace를 다시 검증함 | 전체 검증은 한 번만 실행. 불변 compiled plan을 만들고 프레임 샘플은 같은 수식을 재사용 |
| 액션 완결 | 수치·상태 조건은 있지만 실제 도상, 연기, 가림, 타이포 가독성은 알 수 없음 | 경계 프레임 검사와 실제 재생 검토를 모두 수행. ‘action’이라는 이름만으로 실행 성공 처리 금지 |
| 자동화 기록 | 입력 로그의 모순은 찾지만 로그 밖에서 사람이 작업했는지 증명할 수 없음. 후보 수가 실제 예산과 맞는지도 후속 감사 필요 | 후보 전부·선택·보정·실패를 실행 ID로 수집. 수작업 연구와 자동 평가 결과를 별도로 보고 |

이 문서는 위 한계를 코드에서 이미 수정했다고 주장하지 않는다.

## 3. 13개 논리 자산의 실제 제작 형태

13개는 **논리 자산 ID 수**다. 프로덕션 동작을 13장의 정지 이미지로 해결한다는
뜻이 아니다. 예를 들어 `A02`가 하나의 포즈 ID로 남더라도 실제로는 핵심 그림,
중간 그림, 마스크, 노출 프레임과 앵커 정보를 가진 bundle이 필요할 수 있다.
구성 파일을 늘릴 때 후보·출처·해시 기록에서도 누락하지 않는다.

| ID | 실제로 준비할 소재 | 그림/AI/수치의 역할 | 승인하지 않을 대체물 |
|---|---|---|---|
| A00 | 원본 캐릭터 기준 원화, 의상·얼굴·머리 실루엣·팔레트 기준 | 후보 모델로 생성할 수 있고 사람이 연구용 기준을 선택. 수정했으면 수정 방식 기록 | 현재 CPU LCM 실패 결과 재사용, 기존 작가 캐릭터 복제 |
| A01 | 주머니에 손을 넣기 전후의 핵심 포즈와 짧은 준비 동작 | 실제 어깨·팔·몸의 드로잉 변화. 수치 경로는 손의 도착점과 시점을 고정 | 정지 인물 전체를 기울이는 방식 |
| A02 | 별을 꺼내는 팔·손·옷의 replacement drawing 또는 검증된 짧은 동작 sequence | A00을 계속 기준으로 참조 편집. 팔의 실루엣·옷 주름·주머니 가림을 실제로 그림 | 팔 스프라이트 두 개의 힌지 회전, 투명도 페이드로 자세 교체 |
| A03 | 별을 내민 포즈, 동작 후 옷·머리의 작은 정착 그림 | 멈추는 순간의 연기와 균형을 원화로 설계. 이후 정지는 의도된 hold | 모든 정지 구간에 같은 사인함수 흔들림 추가 |
| A04 | 손을 펴고 별을 놓는 포즈/sequence | 손 펴짐은 실제 형태 변화. 몸과 얼굴은 동작에 맞는 선택된 그림을 유지 | 손을 바꾸는 동안 별이 떠 있거나 손과 합쳐져 녹는 결과 |
| A05 | 문을 발견하며 시선·머리·어깨가 돌아가는 핵심 그림과 중간 그림 | 눈동자만 이동하지 않고 표정·목·어깨의 연기 변경. 임의의 3D 회전 추정 금지 | 얼굴과 몸 전체를 같은 각도로 회전시키는 종이 인형 |
| H01 | 쥔 손. 손바닥/뒤쪽과 앞쪽 손가락의 접촉 레이어 | 별을 가리는 실제 손가락 matte와 grip 등록. 필요하면 연구 단계에서 직접 보정 | 손 위에 별 그림을 무조건 올려놓기 |
| H02 | 반쯤 편 손과 필요한 중간 드로잉 | 손가락 관절·실루엣·접촉면을 확인. 단순 optical flow에 맡기지 않음 | H01/H03 알파 크로스페이드 |
| H03 | 완전히 편 손, 별이 떠난 뒤의 손 | 분리 직전/직후 같은 손과 접점 유지. 별이 손을 떠난 공간이 실제로 비어야 함 | 별 잔상이 손에 남거나 손가락 수가 바뀌는 결과 |
| P01 | 자체 설계 종이별의 앞/뒤 면·접힘 패널·접촉 앵커 | 벡터/래스터 원본을 직접 설계하고 접힘·회전·비행을 수치 제어 | 단순 원/삼각형을 ‘별’ 상태명으로 바꾸기, 크기 변화만으로 펼침 처리 |
| P02 | 별에서 이어지는 종이 띠, 문 윤곽과 열림 mask | 경로·패널·reveal을 명시적으로 제어. 같은 별과 실제 연결 | 완성된 문을 무관하게 페이드인 |
| B01 | 밤 공간의 회화적 원화, 배경/중경/전경 가림 레이어 | 실제 원화에서 붓결과 실루엣을 유지하는 레이어 제작. 가까운 전경은 인물 앞을 의도적으로 가릴 수 있음 | 이전 꽃·삼각형 패턴을 전 화면에 반복 |
| B02 | 문 안쪽 밝은 공간과 깊이 레이어 | 최종 카메라 확대에서 버틸 해상도와 여백. 문 내부 mask로만 보임 | 평면 흰색 플래시로 ‘다른 공간’ 연출 완료 처리 |

AI가 회화풍 그림을 생성했다면 `model_generated`로 기록한다. 실제 사람이 직접
그리지 않은 그림을 ‘수작업 손그림 제작’이라고 소개하지 않는다. 전경 분리·가림막·
등록 좌표·선 정리를 사람이 보정하면 Stage A의 `manual_edits`에 남긴다.

## 4. 중간 동작을 만드는 전략

우선 원화와 5개 핵심 행동 포즈의 미술·인물 일관성을 확인한다. 정지 그림이
실패하면 중간 동작을 대량 생성하지 않는다. 후보 모델은 별도 조사 문서의 후보일 뿐,
아직 해당 모델이 이 그림·손·동작을 성공시킨 상태는 아니다.

첫 동작 제작은 다음 세 방법을 구분해 사용한다.

1. **그려진 핵심/중간 포즈:** 손과 소품 접촉, 팔 실루엣, 어깨·머리 연기는 핵심
   드로잉을 우선한다. 참조 편집 결과의 오류는 선별·보정하고 연구 과정으로 기록한다.
2. **검증한 짧은 생성 동작:** 참조 원화·시작/끝 포즈·구도 조건을 유지할 수 있는
   실제 모델 경로가 확인됐을 때만 사용한다. 전체 15초를 자유 생성에 맡기지 않는다.
   얼굴 drift·손 형태 붕괴·배경 출렁임·물체 복제·접점 오류가 있으면 탈락이다.
3. **제한된 수치 보간:** 인물/소품의 월드 위치, 접촉 앵커, 별의 접힘 패널·비행,
   문 경로, 카메라·가림·타이포 타이밍을 계산한다. 새 손가락·옷 주름·표정을
   선형 워프로 만들어낼 수 있다고 가정하지 않는다.

캐릭터를 24fps로 매 프레임 새로 생성할 필요는 없다. 선택된 작화의 hold와
replacement drawing을 사용할 수 있고, 최종 합성은 24fps로 출력한다. 어떤 노출 간격이
좋은지는 실제 재생으로 판단한다. 프레임 수를 늘렸다는 사실은 자연스러운 동작의 증거가 아니다.

현재 단일 PNG 예약을 그대로 사용해 포즈 사이를 크로스페이드하는 것은 품질 기준에서
실패다. 실제 sequence/bundle이 준비되지 않으면 렌더 준비 불가로 남긴다.

## 5. 손·별 접촉과 fixed-arm IK의 역할

고정된 상완 76/전완 78의 2D IK는 등록 가이드와 오류 검출용이다. IK의 점을 따라
그림 팔 조각을 회전시키는 것은 이 계획의 최종 애니메이션 방법이 아니다.

- A01–A05의 실제 드로잉에 어깨·팔꿈치·손목·grip을 등록한다.
- 드로잉의 접점이 계약의 점과 다르면 원화 등록과 장면 계획 중 무엇이 잘못됐는지
  판단해 명시적으로 보정한다. 그림을 늘려 오차를 감추지 않는다.
- 팔이 카메라 쪽으로 크게 단축되는 포즈는 고정 2D 길이로 표현할 수 없다. 그런
  원화를 채택하려면 시점별 투영 길이/포즈 기준을 계약에 추가해야 한다. 현재 IK가
  단축법이나 해부학을 검증한다고 주장하지 않는다.
- 손의 접촉은 한 점뿐 아니라 grip의 방향과 별의 접촉 가장자리도 필요하다.
  새 asset registration에는 접촉 origin·axis/edge와 앞/뒤 가림 레이어를 추가한다.

중요 구간:

| 프레임 | 필요한 실제 화면 |
|---|---|
| 18–24 | 손이 주머니에 들어가며 손과 주머니 앞면의 가림 순서가 바뀜 |
| 24–42 | 별은 손에 붙어 함께 나오지만 주머니 앞면 mask에 가려졌다가 점진적으로 드러남 |
| 96–131 | 별 뒤 손바닥 → 별 → 앞쪽 손가락의 레이어 관계 유지. 손이 열리며 손가락 가림 면적이 줄어듦 |
| 131–132 | 같은 별의 위치·속도와 접촉 가장자리가 이어짐. attachment 제거로 별이 순간이동하지 않음 |
| 132–192 | 손에는 별 잔상이 남지 않고, 별 자체의 종이 면이 펴지며 독립적인 호 운동을 함 |
| 216–264 | 같은 별이 문의 시작점이 됨. 별/종이 띠/문 윤곽의 연결이 실제 프레임에서 보임 |

H01–H03를 몸 그림 위에 더하는 경우 몸 원화에 이미 그려진 손을 중복 표시하지 않도록
손 영역·소매 접합부를 준비한다. 마스크가 없는 완성 PNG에 다른 손을 겹쳐 합성하지 않는다.

## 6. 회화적 레이어와 2.5D 카메라

현재 sampler는 중심/zoom의 직교 카메라만 계산한다. **아직 깊이별 카메라 합성이나
2.5D 렌더러가 구현된 것은 아니다.** 새 렌더러는 다음을 명시적으로 추가한다.

- B01을 원경·중경·가까운 전경으로 분리하고 각 레이어의 원본 그림·alpha·등록 영역·
  깊이 또는 parallax 계수를 기록한다. 모델의 depth 추정은 실제 3D 복원과 구분한다.
- 캐릭터, 손 앞 레이어, 종이별, 문 패널은 월드와 로컬 좌표를 연결한다.
- 카메라가 움직일 때 가까운 전경은 더 크게 움직이고 먼 배경은 덜 움직이되,
  인물과 소품의 접촉은 같은 투영 안에서 함께 움직인다.
- 전경은 실제 원화의 질감·불규칙한 외곽선을 유지한다. 화면에 질감 필터 하나를
  씌우는 방식으로 회화적 가림 연출을 완성했다고 하지 않는다.
- 새로운 camera roll·깊이 채널은 규격과 compiler가 지원한 뒤에만 사용한다.
  알 수 없는 채널을 조용히 무시하거나 임의의 흔들림으로 대체하지 않는다.

원화에 없는 가장자리를 카메라가 드러내지 않도록 모든 컷의 viewport를 미리 계산한다.
여백이 부족하면 새 배경 확장 소재가 필요하다. 가장자리 늘리기·빈 픽셀·반복 타일로
감추지 않는다. B02는 zoom 7에서 문 안쪽이 화면 전체를 채울 때도 해상도와 구도가
유지되는 실제 공간 원화로 준비한다.

S01의 안정된 전체 구도, S02의 손·별 클로즈업, S03의 공간 reveal과 문 통과는
의도적으로 다른 화면 기능을 갖는다. 단순 확대 컷 세 개를 다른 연출 세 개로 세지 않는다.

## 7. 신규 렌더러의 소비 경로 — 제안, 아직 구현 안 됨

예정 파일명은 `src/voice_motion/mv_directed_renderer.py`다. 기존의 절차적
`MVArtRenderer`에 묵시적으로 fallback하지 않는다.

```text
planning scene JSON + 실제 승인 자산 bundle + 실제 음원/가사/cue
  → validate_scene_plan(require_render_ready=True)
  → media / bundle / registration / music / typography preflight
  → immutable CompiledDirectedScene
  → 동일한 state sampling 수식의 validated fast path
  → actor replacement drawings + 손/별 contact compositor
  → 회화적 배경/전경 depth layers + 2.5D camera
  → 문 mask + 별 접힘/윤곽 + 가사 typography
  → 순차 RGB frames
  → 원음과 H.264/AAC master mux
  → 실제 master에서 VP9/Opus preview 파생
```

`CompiledDirectedScene`의 역할:

- 검증한 자산 경로·해시·원점·crop·alpha·프레임 노출·접촉 mask를 고정한다.
- scene/bundle 전체를 불변으로 취급한다. 렌더 중 파일이 달라지면 실패를 보고한다.
- 샘플에서 나온 actor root/IK/grip, prop state/position/fold, camera, action phase,
  keypose ID를 실제 레이어로 연결한다. 지원하지 않는 동작·부족한 자산은 명시적으로 실패한다.
- 단일 PNG인지 pose sequence인지 확인하고, sequence 구성 파일 전부를 검증한다.
  manifest 한 개만 해시 검사하고 외부 구성 파일을 임의로 읽지 않는다.
- SVG를 쓰면 실행 코드·외부 참조·외부 폰트·스크립트·임의 파일 접근을 거부한다.
  프로젝트에서 직접 작성한 제한된 도형 규격으로 변환하거나 검증된 입력만 래스터화한다.

제안 API는 `compile_directed_scene(scene, asset_root)`와
`render_directed_scene(compiled, audio_path, output_dir, progress)`다.
이 문서는 해당 함수가 존재한다고 주장하지 않는다. 실제 구현 시 최종 인터페이스를 확정한다.

## 8. 실제 렌더 전 preflight

다음은 현재 계약 검사에 **추가할 작업**이다.

1. 이미지/sequence/audio가 실제로 디코딩되고 기대한 길이·크기·색 공간·alpha를 갖는지 검사.
2. bundle 내부 경로·해시·노출 프레임·마스크·앵커가 빠짐없이 연결됐는지 검사.
3. 같은 캐릭터·의상·선 굵기·질감인지 원화/핵심 프레임을 검토. 수치 검사로 대체 불가.
4. 각 그림의 grip/손가락 matte와 별의 접촉 edge가 맞는지 확대 검사.
5. 24/132/216/228/264/288/348 프레임과 컷 경계의 앞뒤를 합성해 실제 가림·상태·카메라를 검사.
6. 실제 가사 텍스트·시간 출처·cue 세 개와 자막 여백을 확정. 빈 cue나 임시 문구는
   `music_ready`가 아니므로 완성 MV 렌더로 진행하지 않음.
7. 현재 샷별 2.5D viewport가 자산의 유효 그림 영역 안에 들어오는지 확인.
8. 자동 후보 예산·후보 전체·선택·수정·실패의 로그 일치 확인. 사람 작업을 누락한 자동화 주장은 거부.

preflight에는 원화와 핵심 프레임 이미지가 필요하지만, 이번 문서 단계에서는 만들지 않았다.

## 9. 합성·타이포·출력

- 같은 인물의 팔레트와 원화 질감을 유지한다. foreground mask에서 반투명 검은 테두리나
  색 번짐이 생기지 않도록 alpha 방식·색 공간을 통일한다.
- 자막은 가사의 의미 단위로 등장·hold·퇴장한다. 글자를 이미지 모델에 생성시키지 않는다.
  시스템 한국어 글꼴을 읽기 전용 참조하면 재배포하지 않고 출처를 기록한다.
- 얼굴·손·별·문 윤곽의 중요한 순간을 피하고, 카메라 변화 뒤에도 가독성을 재검사한다.
  가사가 사건을 대신 설명하도록 만들지 않는다.
- 출력은 우선 960×540/24fps의 15초 master. 필요한 소스 원화 해상도는 클로즈업과
  최종 문 통과 crop을 역산해 정한다. 출력 해상도만 높여 미술 실패를 감추지 않는다.
- 프레임을 메모리에 전부 쌓지 않고 순차 encode한다. 필요한 배경과 소수의 현재/다음
  replacement drawing만 cache한다. 원음은 실제 입력을 사용하고 임의의 대체 음원을 넣지 않는다.
- 생성 모델 실행과 CPU 합성은 순차로 운영한다. CPU codec 최대 2스레드가 기본이다.
  GPU 생성/새 환경/기존 작업 종료는 이 문서의 수행 범위가 아니며 Root의 자원 계획을 따른다.
- 최종 Comfy SDK 경로에는 새 directed renderer를 실제 호출하는 그래프가 필요하다.
  예전 단순 렌더 그래프를 실행한 뒤 새 품질 엔진이 수행됐다고 표시하지 않는다.

## 10. 완료 판단과 다음 단계

성공 증거는 원화 비교·핵심 동작 확대 재생·원음 포함 전체 15초·가사 없는 행동 확인·
후보/수정 기록·실행 재현 정보다. 정지 콘티나 수치 sampler 테스트만으로는 충분하지 않다.

품질 실패 시 원인별로 되돌아간다.

- 원화가 평면 미술/인물 일관성 기준을 못 맞춤 → 원화·참조 편집 검증으로 돌아감.
- 접촉/손/팔 연기가 실패 → 해당 replacement drawing·마스크·앵커를 다시 제작.
- 공간·가림이 실패 → 레이어·카메라·배경 유효 범위를 재설계.
- 음악과 행동이 안 맞음 → cue와 액션 노출 길이 재설계. 무조건 영상 전체 속도 변경으로 감추지 않음.
- 사람이 고른 한 결과만 좋음 → 미술 연구 성공으로만 기록. 자동 제품 성공으로 확대 해석하지 않음.

15초가 통과하면 그다음에 노래 세 구간의 자동 콘티·자산 선택·장면 합성·가사 정렬을
사전에 정한 예산으로 평가한다. 이 제작 계획은 그 자동화 평가를 통과했다는 증거가 아니다.
